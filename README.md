# 局域网快传 LanShare

在电脑上运行一个小程序，同一个 WiFi 下的手机、平板、其他电脑**只用浏览器**就能和这台电脑互传文件和文字，手机上不用装任何 App。

- 手机 → 电脑、电脑 → 手机，双向传文件，几 GB 的视频也可以；WiFi 断一下能断点续传
- 互发文字，一键复制
- **端到端加密**：文件、文件名、文字全程加密；同一 WiFi 下抓包的人看不到你传了什么
- **密钥不经过网络**：扫码时密钥放在网址的 `#` 片段里，不会出现在任何网络请求中；手动输口令用 SPAKE2，抓包也无法离线破解口令
- 单个 2.3 MiB 的 exe、启动约 44 毫秒，没有黑色命令行窗口：主界面是一个独立窗口，程序常驻右下角托盘

v2 用 Rust 重写；v1（Python 版）的代码保留在 `legacy-python/`。

## 安装

已经打包好的 `dist\LanShare.exe` 可以直接双击运行。想像正规软件一样装好（开始菜单、设置 → 应用里可卸载），在项目目录里运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

- 装到 `C:\Program Files\LanShare`，会弹一次 UAC，点“是”
- 开始菜单里会出现“局域网快传 LanShare”，右键可以“固定到任务栏”
- 自动在 Windows 防火墙里放行入站连接（专用和公用网络都放行：Windows 常把家里的 WiFi 默认归为“公用网络”）
- 重新运行 `install.ps1` 就是更新，正在运行的会被自动关掉；卸载在“设置 → 应用”里找“局域网快传 LanShare”
- 没有管理员权限时可以加 `-CurrentUser`：装到 `%LOCALAPPDATA%\Programs\LanShare`，但不会改防火墙

## 怎么用

1. 从开始菜单或任务栏打开“局域网快传”，会弹出主界面窗口，右边有二维码和口令。
2. 手机连上和电脑**同一个 WiFi**，用手机**相机**扫二维码，就能进入。
3. 不方便扫码的设备（比如另一台电脑）：在浏览器里输入主界面上的地址，再输入 6 位口令。
4. 两边都能：
   - 发送文件：手机上点“选择文件发送”；电脑上直接把文件拖进窗口
   - 下载文件：手机上点文件名下载；电脑上点文件会在资源管理器里定位它
   - 发文字、点“复制”
5. 关掉主界面窗口后，程序仍在右下角托盘里运行（Windows 11 可能收在“^ 显示隐藏的图标”里）：
   - 左键单击托盘图标：重新打开主界面
   - 右键：打开共享文件夹 / 退出
6. 再次从开始菜单或任务栏打开时，如果它已经在运行，只会把主界面再打开，不会重复启动。

**文件存在哪？** 所有收到的文件都在电脑的 `下载\LanShare` 文件夹里。重名时自动改名为 `名字 (1).扩展名`。网页上不能删除文件，要删的话点“打开文件夹”到资源管理器里删。

**电脑上的程序重启后**，密钥和口令都会换新，手机需要重新扫码（页面会提示）。想让所有连过的设备立即失效，也是这个办法：从托盘退出再打开。

## 连不上 / 常见问题

| 现象 | 处理 |
|---|---|
| 手机扫码后打不开页面 | ① 确认手机和电脑连的是同一个 WiFi（手机别用流量）。② 访客网络 / 公共 WiFi 常会禁止设备之间互访，换成主网络。③ 没用 `install.ps1` 安装时，第一次运行要在防火墙弹窗里允许访问。 |
| 二维码地址不通，但电脑开着 VPN / 代理 / 虚拟机 | 主界面“手机连不上？”里列出了其他地址，在手机浏览器里手动输入，再用口令登录。 |
| 用微信扫码打开后下载不了文件 | 微信内置浏览器有限制，点右上角“…”选“在浏览器打开”，或者直接用手机相机扫码。 |
| 页面提示“二维码已过期” | 电脑上的程序重启过，重新扫码即可。 |
| 提示“口令登录已暂停” | 有人连续输错口令太多次。在电脑的主界面上点“重新开启口令登录”（会换一个新口令），或者直接扫码。 |
| “复制”提示复制失败 | 少数手机浏览器不允许网页写剪贴板，长按文字手动复制即可。 |
| 启动时弹窗“启动失败” | 一般是 8000 起的 10 个端口都被占用了。关掉占用的程序，或用 `LanShare.exe --port 9000`。 |
| 出了别的问题 | 日志在 `%LOCALAPPDATA%\LanShare\lanshare.log`。 |

## 安全说明

详见 [`docs/SECURITY.md`](docs/SECURITY.md)。要点：

- **防的是窃听**：同一 WiFi 下抓包的人看不到文件内容、文件名、文字、密钥、口令。
- **不防主动攻击**：如果有人在网络里主动做中间人（ARP 欺骗、恶意热点），可以篡改手机加载的页面。这是“手机只用浏览器、不装 App”这类工具的共同上限。在不信任的网络上（咖啡馆、机场）不要传敏感文件，用完从托盘退出。
- **拿到二维码或口令的人就能看到共享文件夹里的所有文件**。只让信任的人扫码；不想共享的文件不要放进去。
- 口令输错有限速：同一设备 60 秒内最多 5 次；累计 30 次没登录成功的尝试后，口令登录自动暂停，要在电脑上重新开启。
- 文件存到电脑上以后不加密（加密只保护传输过程）。
- “在文件夹中显示”“打开文件夹”只对这台电脑自己的主界面开放。
- 文字消息只存在内存里（最多 50 条），程序退出就清空了。

## 命令行参数

```
LanShare.exe [--port 8000] [--dir 共享文件夹] [--no-browser] [--no-tray] [--info-file 路径]
```

| 参数 | 说明 |
|---|---|
| `--port` | 起始端口，默认 8000，被占用时自动往后找 |
| `--dir` | 共享文件夹，默认 `下载\LanShare` |
| `--no-browser` | 启动后不打开主界面窗口 |
| `--no-tray` | 不用托盘，前台运行（Ctrl+C 退出），适合命令行和自动化 |
| `--info-file` | 启动后把端口、口令、密钥写进这个 JSON 文件（给自动化测试用，注意保管） |

不带 `--port` / `--dir` 启动时保持单实例；指定了其中任何一个就会另起一个独立实例。

## 从源码构建（开发者）

需要 Rust（stable，MSVC 工具链）、`wasm32-unknown-unknown` 目标和 Node.js 20+：

```bash
rustup target add wasm32-unknown-unknown
cargo test --workspace                       # Rust 测试
cargo build -p lanshare                      # 互通测试要用 debug 版 exe
node --test "web-tests/*.test.mjs"           # 浏览器端协议、WASM、真实 exe 互通
cargo run -p lanshare -- --no-tray --port 8765 --dir ./tmp-share   # 前台运行
```

一条命令出成品（编 WASM → clippy → 全部测试 → release 构建 → 拿 release 版 exe 再跑一遍互通测试）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1
```

产物在 `dist\LanShare.exe`，再运行 `install.ps1` 安装或更新。
